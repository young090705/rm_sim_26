# MuJoCo 哨兵仿真

用于**物理参数辨识**与**云台系统辨识**。Gazebo 那套不动——两者分工不同：

| | Gazebo (`../`) | MuJoCo (本目录) |
|---|---|---|
| 用途 | 导航栈开发 | 参数辨识、控制器调参、强化学习 |
| 依赖 | ROS 2 + RGL 雷达插件 + RMUC 场地 | 只要 Python |
| 速度 | 实时 | 无渲染时约 300 倍实时 |
| 优势 | 与真车同一套 ROS 接口 | 解析动力学、质量矩阵可直接读、可批量并行 |

不建议把导航仿真整体迁到 MuJoCo：RGL 的 Mid360 点云仿真和 RMUC 场地资产都在 Gazebo 侧，重做代价大而收益低。

## 环境

```bash
cd mujoco
uv venv && uv pip install -e .
uv run sentry-mj                    # 直接跑，模型与网格都已入库
```

改了 `../models/sentry/model.sdf` 之后重新生成：

```bash
uv pip install trimesh
uv run python tools/glb_to_obj.py           # GLB -> OBJ
uv run python tools/gen_mjcf.py             # -> models/sentry.xml
uv run python tools/verify_against_sdf.py   # 确认与 SDF 一致
```

## 运行

```bash
uv run sentry-mj                      # 交互式查看器
uv run sentry-mj-id --all             # 三轴惯量辨识
uv run sentry-mj-id --all --friction  # 额外做摩擦分离
```

### 操作

| 按键 | 作用 |
|---|---|
| `V` / `1`~`6` | 切换视角 |
| `X` | 发射一发 |
| `B` | 连发开关 |
| `N` | 摩擦轮启停 |
| `R` | 复位 |
| `P` | 打印状态 |

`Space`、`Tab`、`Backspace`、`[` `]`、`Esc`、`F1`~`F5`、方向键归 MuJoCo 查看器自身使用（暂停、切面板、复位、循环相机等），按下不会传到回调，所以自定义功能全部避开。

六个视角：自由、跟随（后方/侧方/俯视）、云台自瞄相机、雷达位。

`config.toml` 支持热重载——仿真运行中保存即生效，改初速、增益、扫描参数不用重启。解析失败时沿用当前值。

## 模型来源

MJCF 由 `tools/gen_mjcf.py` 从 `../models/sentry/model.sdf` **自动生成**，不手抄参数，两个模型因此不会各自漂移。改了 SDF 就重跑一次。

```
../models/sentry/model.sdf     几何、位姿、质量、惯量的唯一来源
        │
        ├─ tools/glb_to_obj.py     GLB 按材料分组 → OBJ（MuJoCo 不认 GLB）
        └─ tools/gen_mjcf.py       → models/sentry.xml
                │
                └─ tools/verify_against_sdf.py   交叉校验
```

### 交叉校验

`verify_against_sdf.py` 用两条**完全独立**的路径算同一批量：MuJoCo 的质量矩阵对角元 `M[i,i]`，与 SDF 侧的平行轴定理。当前全部 0.00% 一致：

```
项                          MJCF刚体          SDF       相对差   armature
总质量 kg                    27.5136      27.5140     0.00%
wheel_*_joint             0.00320      0.00320     0.00%    0.00200
big_yaw_joint             0.23681      0.23681     0.00%    0.00400
small_yaw_joint           0.01854      0.01854     0.00%    0.00400
pitch_joint               0.01491      0.01491     0.02%    0.00400
```

改任何模型参数后都该重跑一次——它能在辨识出问题时，帮你区分「辨识没收敛」和「模型本来就错了」。

## 辨识

### 为什么先在仿真里做

模型里的 J 本来就是已知的，辨识它没有信息增益。价值在于**先验证辨识流程本身**：用真值已知的系统跑一遍，估计值若回不到真值，说明激励设计、样本筛选或最小二乘有问题——那么同一套流程用在真车上，得到的数同样不可信，而且你无从发现。

这一步实际抓出了四个 bug，每个都会让真车辨识失败且难以察觉：

| 现象 | 根因 | 修法 |
|---|---|---|
| pitch 惯量为负，R²=0.15 | 恒幅值扫频在低频段需要 33 rad 位移，而限位只有 0.9 rad，90% 样本被顶在限位上 | 恒位移扫频（力矩幅值 ∝ f²）+ 剔除触限样本 |
| big_yaw 惯量偏低 25% | 碰撞体互相穿透——轮子的碰撞球嵌在底盘圆柱里，底盘又与云台圆柱重叠，凭空产生 33 个接触约束 | `<contact><exclude>` 屏蔽机体自碰撞，等价于 SDF 的 `self_collide=false` |
| big_yaw 惯量仍偏低 | 底盘自由时被云台反作用推着反转，等效惯量小于锁定值 | 编译期删掉底盘自由关节（对应真车固定在台架上），而非运行时清零速度 |
| 摩擦 b 误差 80% | 扫频里 `dq` 与 `sign(dq)` 高度相关（条件数 ~400），最小二乘分不开粘滞与库仑 | 恒速法：多个恒定转速下测稳态力矩，速度成为自变量 |

### 当前精度

```
惯量（恒位移扫频，台架）      摩擦（双向恒速）
big_yaw     0.01%           b 2.3%
small_yaw   4.33%           b 1.6%
pitch       0.53%           b 7.0%
```

### 关于 armature

MJCF 的 `armature` 就是折算转子惯量 `N²·J_rotor`，是辨识的目标之一而非固定值。当前值（云台 0.004、轮 0.002）是占位初值。

它占总惯量的比例差别很大：big_yaw 只有 1.7%，pitch 达 21.2%。这解释了为什么小惯量轴的实测 J 常显著高于 CAD 值——不是 CAD 算错，是转子惯量按传动比平方折算后不可忽略。大 yaw 的同步带经 CAD 实测为 1:1，所以 N 只来自 DM4310 自身减速比。

### 用于真车

`friction_sweep` 的双向恒速法和显式重力项拟合都不依赖仿真特权（不需要「关掉重力」），可直接搬到台架。步骤不变：固定底盘 → 单轴激励、其余轴钉住 → 恒位移扫频辨 J → 双向恒速辨摩擦。

## 弹丸

17mm、3.2 g，绿色荧光材质，预建 24 发的对象池（结构固定，可直接用于 MJX 批量仿真）。

**由摩擦轮真实加速，不是设定初速。** 两个摩擦轮（CAD：57 g、ρ=1602 聚氨酯、半径由惯量反推约 30 mm）夹住弹丸，速度伺服控转速，弹丸靠接触摩擦加速出膛。所以 `config.toml` 里没有 `muzzle_speed`——初速是 `fric_speed` 的结果，可以拿去和真车实测对照。

摩擦轮未达转速时拒绝发射，与真车一致。

受力全部交给 MuJoCo，不手写弹道：`<option density="1.204" viscosity="1.8e-5">` 加 geom 的 `fluidshape="ellipsoid"`，得到阻力、升力、马格努斯力和角阻尼。`config.toml` 里把 `spin_rpm` 调到非零，可以观察自旋对落点的影响。

### 步长与出膛

摩擦轮转速 855 rad/s 时，`dt=1 ms` 每步轮子转过 **52°**、接触点划过 **27 mm**——比弹丸直径 17 mm 还大。摩擦求解器把这一整步当成恒定滑移，相当于把弹丸焊在轮面上。步长收敛检验：

| dt | 每步转角 | 出膛 m/s | 与上一档差 |
|---|---|---|---|
| 2e-3 | 103° | 22.33 | — |
| 1e-3 | 52° | 24.17 | 8.2% |
| 2e-4 | 10.3° | 18.03 | 25.4% |
| 5e-5 | 2.6° | 17.80 | 1.3% |
| 2e-5 | 1.0° | 17.72 | 0.45% |
| 5e-6 | 0.3° | 17.69 | 0.20% |

`dt=1 ms` 的 24 m/s 落在收敛区外、偏高 36%，而且**错得好看**——它接近轮面线速度 25.7 m/s，看着像"理论上限"。收敛值 17.7 m/s（效率 69%）才是真的，摩擦轮发射本来就有打滑和弹丸压缩损耗。

经验法则：**旋转接触的步长上界由每步转角定，不是由刚度定**，取 ≤2°，即 `dt ≤ 0.035/ω`。改摩擦轮转速时步长要跟着改。

只在弹丸靠近摩擦轮（70 mm 内）时降到 `launch_dt`，其余保持 1 ms。起初用的是"发射后固定 12 ms 窗口"，但弹丸以送弹速度爬行约 10 ms 才被两轮咬住，咬合时刻恰好卡在窗口边缘，同一份配置能打出 18.5 和 24 两种初速。改成按距离判定后 8 发标准差 0.28 m/s。

枪口位置取自 CAD 的 RM18 裁判系统测速模块中心 `(-23.0, 257.3, -54.3) mm`（pitch 系），枪口设在中心线上、模块后方 60 mm，弹丸自后向前贯穿。实测发射方向与中心线夹角 0.00°、轨迹距中心最近 1.9 mm（该残差是重力在 60 mm 飞行距离上的下坠）。`chrono` site 标出模块中心，便于目视确认。

真车靠这个模块测初速，所以这条中心线必须对——最初按目测放的枪口高了 194 mm，弹丸从模块旁边飞出去了。

## 已知取舍

- 碰撞体是粗包络（底盘/云台圆柱、轮子球），够用于接触与弹丸命中，但不适合精细的装甲板判定
- 全向轮用各向异性摩擦的球近似，没有逐辊子建模。切向抓地、轴向近乎自由，对底盘运动学足够；研究辊子过渡时的抖动则不够
- `pitch` 与 `small_yaw` 的关节限位沿用 SDF 里的估计值，待实车确认
- 视觉网格共 93 万面，30 Hz 下约 0.83 倍实时；要更快就降 `--render-hz`，或做大批量并行时换成原语碰撞体
- 关窗时 GLFW 在本机 NVIDIA 驱动上会段错误（最简模型同样复现，与模型无关），`viewer.py` 用 `os._exit` 跳过该清理路径
